在 ColorOS 上还原魅族 Flyme 小窗「呼之即来，挥之即去」的手感 —— **不需要 root，不需要 Xposed，不写一行 hook。**

## 这是什么

魅族 Flyme 的小窗，把「呼之即来，挥之即去」做得轻巧又顺手。几次简单的滑动与轻点，便能处理眼前的小事。ColorOS 有小窗但入口不同、手感也不同，这个项目把它搬了过来 —— 而且完全不依赖系统级修改。

角落斜向内上滑 → 扇形菜单展开并跟随手指 → 松手 → 应用以小窗形态打开。

## 与上游的关系

本项目是 [Mangi-11/FlymeFreeform](https://github.com/Mangi-11/FlymeFreeform) 的衍生作品。上游通过 **libxposed API** 直接 hook SystemUI / system_server 来实现等效功能，需要 root 或 Xposed 环境。

本仓库把实现路径整个重写了一遍：**不 hook 任何系统进程**，改用普通应用就能拿到的三样能力。两者没有代码依赖，可分别安装、互不影响。详细来源与授权说明见 [NOTICE.md](NOTICE.md)。

## 怎么做到的

| 能力 | 承担者 | 用途 |
| -- | -- | -- |
| 看 | 无障碍服务 | `getWindows()` 拿到全部窗口边界，从而识别出当前的小窗、算出遮罩该铺在哪 |
| 画 | 系统悬浮窗 | 角落手势触摸条、扇形菜单、窗外遮罩、应用面板，全部自绘 |
| 动 | 无障碍手势（默认） | `dispatchGesture()` 在小窗底部的小横条上重放一次「快速上滑」，这是 ColorOS 手势模式自带的关闭动作 |
| 动（可选） | Shizuku（shell 身份） | 读系统日志拿到小横条的真实坐标、注入触摸、强行停止应用、以及**把被系统清掉的无障碍开关写回去** |

一条关键教训写在代码注释里：`setMotionEventSources()` 是**独占截断**而不是「观察」—— 开启后事件不再派发给系统，会直接把设备卡死。所以感知全局触摸这件事，本项目走的是「自己铺一层透明窗口接收」的路子，而不是去截系统输入。

## 功能

- **角落手势唤出**：左下 / 右下角斜向内上滑唤出扇形菜单，划过图标时有马达触感反馈。松手时手指若没停在图标上，轮盘会**保持显示（粘滞态）**，此时滑动与点击同样有震动——点图标直接启动，点空白收起。两个角可分别开关，触摸区宽高、屏幕边缘预留都能在设置里调。
- **扇形菜单**：**张角固定 86°**，项数只决定弧内怎么均分——加项时弧的边界不动，图标在弧内重新排布，所以「已选」增删不会让整个轮盘跳位置。「更多」固定占最低端那一格。可调的是**半径**（扇形宽度 / 高度）、**离屏幕角落的距离**与**图标直径**；只画原始图标，无遮罩、无应用名 —— 对齐魅族官方截图的观感。图标不封顶，调得比弧上的格子大时会相互重叠（有意的，按观感自己取）。
- **以小窗启动**：优先用 `startActivity` 直接带 `windowingMode`；被拒时回退 Shizuku `am start`。
- **应用固定**：扇形里最多 6 个，可在面板里的「已选」条上**长按拖拽排序**，也可在独立管理页用 ↑↓ 调序。新加入的插在**最靠近「更多」**的那一格，「已选」条上则落在最右端。
- **「更多」面板**：自绘的圆角卡片式面板，分成 **应用 / 工具** 两个标签页 —— 标签是**两个各自独立的按钮**（不是一条灰底里嵌两段），两栏是**各自独立的页面**，左右滑动翻页（跟手拖动、松手吸附）。**标签栏上方有一条「已选」**（应用与工具都在里面，两页共用），滚动时它会**跟手收缩高度被推走**，停下来即回到原位——这样它既始终可见、又不占着屏幕。应用页往下依次是「最近使用」（自动记录最近打开的 8 个**应用**，不混入工具）和 A–Z 分组网格（右侧首字母索引条）。卡片**下方**还有一行「固定栏」，最多放 4 个一键入口，无背景、只认图标本体的点击。
- **固定项增删**：点右上角「管理」进入管理模式 —— 未加入的画**绿底白「＋」**（点它加入扇形），已加入的画**红底白「－」**（点它移出）。两条固定条（「已选」与卡片下方「固定栏」）在管理模式下同样亮起红「－」，点一下即从该条移出。也可以长按图标，在弹出的操作卡里选「加入 / 移出扇形」或「加入 / 移出固定栏」。
- **内置工具（10 个）**：识屏、截屏、手电筒、录音、便签、微信扫一扫、支付宝扫一扫、微信付款码、支付宝付款码、一键锁屏。
  - **识屏**：**重放「双指长按」**唤起 ColorOS 原生的「小布识屏」（它没有任何公开入口，连同类第三方实现用的智能侧边栏 feature scheme 在 ColorOS 17 上也已失效）；无障碍没连上时才退回本项目自己读无障碍文字。
  - **扫一扫 / 付款码**：按**显式组件 + extra** 直达页面（微信的 `weixin://` 功能 scheme 已被其新版关闭，支付宝需要 `chInfo=ch_oppoSide`）。
  - **截屏**：走无障碍截屏并存到相册 `Pictures/FlymeFreeform`——**不需要存储权限**，也没有录屏授权弹窗。
- **窗外点击关闭**：点小窗外任意位置关掉小窗。默认在小窗底部横条上模拟一次「**快速上滑**」（ColorOS 手势模式自带的关闭手势），落点按小窗边界估算，**不依赖任何第三方**。需要的话可在「高级设置」里换成两种**免校准**方式：从 ColorOS 自己的日志里读出小横条的真实坐标（`mStartHandleBottomPoint`），再在真坐标上「上滑关闭」或「单击关闭」——这两种需要 Shizuku。
  - **这个动作的语义只有一种：关掉小窗。** 想把它收成边上的迷你浮窗，请用 ColorOS **原生手势**（自己在小横条上滑），本软件不介入——早先试过「点窗外改收迷你」，实测那不成立，反而把关闭本身也弄坏了，已整体下线。
  - **软键盘弹出时会自动让开键盘区域**，在小窗里打字不会误关小窗。
  - 页面默认只露「开关」和「去开无障碍」两项，其余调参项收在**「高级设置（一般不用动）」**折叠区里。
- **角落点击透传**：角落触摸条吃掉的那次按压，按原坐标、原时长重新注入一次，等效于用户真的点在那里（长按也会还原成长按）。
- **无障碍权限的「保持」**：ColorOS 会在若干情形下把无障碍开关清掉（本应用自己没权限写回）。为此做了三条通道：
  - **快捷设置磁贴**：亮 = 就绪，暗 = 点一下就走 Shizuku 把它写回来；
  - **自动恢复**：开机、应用更新后（以及 Shizuku 刚连上时）自动检查并补写，只追加自己、不动其它无障碍服务；
  - **持久化诊断**：把关键事件写进 `filesDir/a11y-trace.log`（最多 60 行，不受调试开关影响），重启后仍在，并会合并进设置里的日志页。
  - 同时，所有系统回调都包在 `safeRefresh()` 里：回调里抛异常会被系统**直接停用**这个无障碍服务，用户看到的就是「重启后权限没了」；窗口事件也合并成一次重排，避免主线程被 IPC 占住而被判无响应。

### 设置在哪

主界面按「授权与状态 → 设置 → 调试」排列，设置下有三个二级页：

- **主动呼出**：左下 / 右下开关、触摸区宽高与边缘预留、扇形设置（宽高 / 离角距离 / 图标大小 / 呼出晃动）、划过图标时震动、角落点击穿透、图标包，以及各自分组的「恢复默认」。
- **窗外点击关闭**：总开关、去开无障碍，其余在「高级设置」里（只遮左右两边、关闭方式、上滑距离/时长、落点校准与准星、Shizuku 兜底与覆盖范围显示）。
- **应用管理**：扇形里固定的项，可调序、可移出。

### 已知限制

- **点窗外收迷你浮窗**：不做。「点窗外」的语义就是关掉小窗；收迷你交给 ColorOS 原生手势。实测「拖窗口右下角缩到最小」在 ColorOS 17 上得到的是关闭，没有可用的注入入口。
- **小布识屏 / 一键闪记**：ColorOS 内部功能，不对第三方开放调用，无 root 无法直接唤起（面板里的「识屏」是**重放双指长按手势**，让系统自己去响应）。
- **识屏读不到图片里的字**：它读的是界面**主动暴露给无障碍**的 `text` / `contentDescription`，图片、视频与网页画布（Canvas 绘制的字）读不到。这是不引入 OCR 引擎时的能力上限。
- **原生侧边栏的「全部」面板**无法复用（需要往 `com.coloros.smartsidebar` 注入 Binder），已用自绘的「更多」面板替代。
- **角落触摸条是独占窗口**：落在它方块内的触摸都会被它消费，这是悬浮窗机制本身的副作用，「角落点击透传」就是为了缓解它。
- **三键导航下角落手势不生效**（设计如此，不是缺陷）。
- **只在 ColorOS 上验证过**：本项目按 ColorOS 的窗口行为与小窗手势调参，其它 ROM（含原生 Android、其它厂商定制）不保证可用。

## 权限说明

这个项目要的权限偏多，逐条说明都是干什么的，请自行判断：

| 权限 | 用途 |
| -- | -- |
| 显示在其他应用上层 | 绘制角落触摸条、扇形菜单、遮罩与面板。核心权限 |
| 无障碍服务 | 读取窗口边界以识别小窗、注入手势、铺设窗外点击接收层；「识屏」会读取当前界面暴露给无障碍的文字（**仅在本机内存里处理，不上传**）；「截屏」用它的截图能力（无存储权限、无录屏弹窗） |
| Shizuku（`moe.shizuku.manager.permission.API_V23`） | 以 shell 身份注入触摸、执行 `am` / `settings` 命令。**可选**：不授权也能关闭小窗（走无障碍手势），但「免校准关闭方式」「强停应用兜底」「把无障碍开关写回来」这三项要用它 |
| 查询所有已安装应用 | 渲染应用列表与「更多」面板 |
| 通知 / 前台服务 | 保持角落手势服务常驻，状态栏有常驻通知 |
| 开机自启 | 系统重启或应用更新后自动恢复呼出服务与 Shizuku 监听 |
| 震动 | 扇形菜单划过图标时的触感反馈 |
| 设备管理 | 「一键锁屏」工具用它执行 `lockNow()`，需你在系统设置里手动激活一次（可随时关闭） |

两点补充：**手电筒**走的是不需要权限的 `setTorchMode`，本应用**没有申请相机权限**；**截屏**通过 MediaStore 写入相册，**没有申请存储权限**。

## 构建

要求 JDK 17、Android SDK Platform 37（`platforms;android-37.0`）与 build-tools 36.0.0。SDK 位置写在根目录 `local.properties` 的 `sdk.dir`（该文件不提交）。

```bash
./gradlew :app:assembleDebug
```

产物：`app/build/outputs/apk/debug/FlymeFreeform-<版本>-Debug.apk`

编译目标：`compileSdk 37` / `minSdk 35` / `targetSdk 37`，版本号来自根目录 `gradle.properties` 的 `flymeFreeformVersionCode` 与 `flymeFreeformVersionName`。

> 注意：**不要**给这个模块显式加 `org.jetbrains.kotlin.android` 插件 —— AGP 9 自带 Kotlin 支持，额外声明会让 Gradle 报 “plugin is already on the classpath with an unknown version”。

## 下载 / CI

不想自己配环境的话，直接用 GitHub Actions 产出的 APK：

- **每次提交**：在 [Actions](../../actions/workflows/build.yml) 页面选最新一次成功的运行，页面底部 **Artifacts** 里的 `FlymeFreeform-debug-apk` 就能下载。
- **正式发版**：推一个 `v*` 标签（如 `git tag v0.6.23 && git push origin v0.6.23`），会自动建 Release 并把 APK 挂上去，可直接下载安装。

CI 配置在 [`.github/workflows/build.yml`](.github/workflows/build.yml)：JDK 17 + Android SDK（`platforms;android-37.0`、`build-tools;36.0.0`）+ Gradle。产物是 **debug 签名**的 APK，可直接安装体验。
